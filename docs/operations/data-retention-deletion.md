# データ保持・削除方針（ドラフト）

Status: Draft / 専門家確認前。Issue #12 の「データ保持」「通報・緊急停止」「プライバシー」に基づく初版です。

## 1. 標準では映像を保存しない

- IRLight は標準で映像・音声パケットを録画・保存しません。
- デバッグ目的でも、映像・音声を無断で保存しません。
- 証拠保全が必要な場合も、metadata と既存の監査記録を基本とし、映像の保存は別途の運用判断・法的根拠を必要とします。

## 2. 保持対象と目的

| データ | 目的 | 備考 |
| --- | --- | --- |
| ユーザー登録情報 | 認証・サポート・法令対応 | 物理削除 / 匿名化は要判断 |
| Destination 設定と暗号化 secret | 配信先設定 | 平文 secret は保存しない |
| 待機素材 | 配信利用 | `PROCESSING` 完了は worker の安全証明ではない（脅威モデル T05） |
| Session metadata | 運用・監査・利用量計上 | 削除・保持期間は要確認 |
| 接続・切断・障害 event | 障害対応・監査 | 高頻度 event / payload 上限の契約を維持 |
| 利用量・決済 | 課金・会計 | 法令・会計上の必要期間を優先 |
| 監査ログ | セキュリティ調査・改ざん耐性 | 改変困難化・保持期間は要判断 |

## 3. 保持期間の区分

- 契約・会計・税務上必要な期間: 法令・会計を優先し、IRLight の一般運用より長い場合があります。
- 運用・監査 metadata: 障害調査・不正調査に必要な期間保持します。
- 退会要求対応: 削除要求受付時の記録と、削除完了の証跡を必要な期間保持します。

具体的な日数・年数は【要確認】です。未確定の期間を「確定済み」と扱いません。

## 4. 削除フロー

1. 要求受付（本人確認・対象アカウント / Session の特定）
2. 削除対象の特定（登録情報、Destination、待機素材、Session metadata、関連 storage）
3. 法令・会計・監査上必要な保持データの分類（削除不可 or 匿名化）
4. 削除実行と完了記録
5. 関連 credential / ingest secret / destination runtime secret の失効確認
6. 必要に応じた補填・返金・異議申立て窓口への接続

削除は irreversible な操作のため、実行者は対象範囲・影響を記録しつつ、runbook に従って行います。

## 5. 通報・緊急停止時の保全

- 公開通報窓口および緊急停止 runbook により、対象 Session / ユーザーの即時停止が可能です。
- 保全対象は、Generation・Session・Node・時刻・operator・理由などの metadata を基本とします。
- 不正配信が継続している場合、ingest credential と destination secret 配送を失効します。
- 証拠としての metadata 保全期間と、誤通報・異議申立て・反復違反者の扱いは運用判断・法務確認が残ります。

## 6. 管理者権限と監査

- 緊急停止権限と secret 復号権限の分離、RBAC、MFA、管理操作監査、改変耐性は Issue #12 の未実装残件です。
- 通常のユーザーサポートで配信キーを閲覧しないことと、監査ログの改変を困難にすることは目標とします。
